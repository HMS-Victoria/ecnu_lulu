## 一、目标（Objective，粘进目标框）

> 在本工作区交付一个可在 Windows 上直接运行的带 GUI 的桌面应用「大夏学堂录播转写助手」：它使用我本人的华东师范大学账号（学号见本地配置）登录 `https://courses.ecnu.edu.cn/jy-application-resourcemanage-ui/#/home` 录播平台，自动拉取我账号有权限访问的全部录播视频清单并在界面中展示；我勾选任意条目后，应用负责把对应视频的**音频**取回本地、调用我配置的语音识别接口转为文本，并把转写结果（`.txt` / `.srt` / `.md` 摘要）保存在我指定的本地目录，全程可断点续跑、可查看进度、日志可追溯。最终必须能打包出一个双击即可运行的 `.exe`，并用自己的真实账号完成至少 2 条视频的端到端验收。

## 二、支撑上下文（作为首轮消息发送）

### 0. 角色与工作方式

你是本项目的端到端交付工程师。请按下面的里程碑推进，**每一轮结束时更新工作区里的 `PROGRESS.md`**（当前里程碑 / 已完成 / 下一步 / 阻塞 / 可复现的证据命令与输出），不要把中间过程只留在对话里。

规则：

- 遇到**必须由我决策**的分叉点（ASR 供应商选型、输出格式、是否打包单文件 exe、是否保留原始视频），先用提问工具问我，不要自己拍板。
- 遇到**纯技术问题**自己能解决的，不要来问我，直接做。
- 每一步都要有可验证的证据（命令 + 真实输出），不允许把「应该可以」当作「已完成」。
- 交付即文件：代码、`README.md`、`API.md`、`requirements.txt` 都必须落在工作区里。

### 1. 目标平台的事实（先按此假设，再用实测校正）

- 站点是**前端 SPA**（Vue 路由带 `#/`），URL：`https://courses.ecnu.edu.cn/jy-application-resourcemanage-ui/#/home`。
- 登录走**学校统一身份认证（CAS/OAuth 跳转）**，账号是学号。这意味着**登录环节很可能有验证码或二次验证**，无法纯自动化。
- 数据来自 XHR/Fetch JSON 接口；视频大概率是 **HLS（`.m3u8` + AES-128 分片）或 mp4**，播放地址通常带**时效性签名参数**。
- 上述每一条都要在 M0 阶段用真实抓包证实或推翻，**以实测为准**，不要照抄假设写代码。

### 2. 硬性技术约束

- 语言/运行时：**Python 3.11+**；GUI 用 **PySide6**（若 PySide6 在你的环境不可用，退到 Tkinter 并在 `PROGRESS.md` 说明原因）。
- 网络：`httpx`（同步）+ `playwright`（仅用于登录与抓包）。
- 媒体：`ffmpeg`（随包携带 `ffmpeg.exe`，可用 `imageio-ffmpeg` 提供），所有下载/切片/转码必须走 ffmpeg。
- 状态：`sqlite3`（`state.db`），任务表字段至少 `id / course / resource_id / title / stage / progress / retry / error / output_dir / updated_at`。
- 打包：`PyInstaller`（优先 `--onedir`，稳定优先于体积），产物放在 `dist/`。
- 依赖锁定到 `requirements.txt`，含版本号。
- 目录约定：
  - `src/ecnu_transcribe/`（核心库：client / downloader / transcriber / pipeline / store）
  - `src/app/`（PySide6 界面）
  - `output/<课程名>/<标题>.{txt,srt,md}`（默认输出，可由用户在设置里改）
  - `cache/media/`（音频缓存，便于重跑不重下）
  - `recon/`（抓包产物，**必须脱敏**）、`docs/`、`PROGRESS.md`

### 3. 里程碑与每轮验收

**M0 — 侦察（必须先做，不许跳）**

1. 用 Playwright `launch_persistent_context()` 打开一个**可见**的 Chromium，持久化目录放在 `%LOCALAPPDATA%\ecnu-transcribe\browser`，导航到上述 URL，**让我手动完成统一身份认证**（我在场时按提示操作），登录成功后保存 `storage_state.json`。
2. 期间挂 DevTools 协议监听所有 `XHR/Fetch` 请求与响应，原始记录写入 `recon/network.jsonl`（**脱敏**：删掉 Cookie / Authorization / 密码 / 手机号）。
3. 反推出这些接口并写进 `docs/API.md`（每个接口要有：URL、方法、必要 header、查询参数、请求体、响应字段样例、分页方式、鉴权方式与有效期）：
   - 课程 / 开课列表
   - 课程下的资源（录播 / 回放 / 章节）列表
   - 单个资源的播放地址与音视频元信息
   - 登录态如何维持（Cookie 名、token 存放位置、过期表现）
4. **验收**：`docs/API.md` 里每条接口都附上真实返回样例；并且能用一个最小 httpx 脚本（`scripts/fetch_catalog.py`）在**不带浏览器**的情况下拉回至少一页真实课程/资源 JSON。

**M1 — 清单客户端**

- 实现 `EcnuClient`：自动复用 `storage_state.json`；能翻页拉全量；登录态失效时抛出明确的 `AuthExpiredError` 并**不静默重试成空列表**。
- 产出 `data/catalog.json`，字段至少：`course_id, course_name, teacher, resource_id, title, duration_sec, record_time, mime, size_hint, play_url`。
- **验收**：打印「课程数 / 资源总数 / 时长合计」，并把前 3 条贴进 `PROGRESS.md`；数量与我登录网页看到的一致。

**M2 — 音频获取**

- 用 ffmpeg 从 `play_url` 拉流并只留音频：`-vn -ac 1 -ar 16000 -c:a libmp3lame -b:a 64k`（或 wav/pcm，按 ASR 端点要求）。
- 支持：HLS 分片、AES-128 加密（key 请求要带同样的 Cookie/Header）、`.m3u8` 里的相对路径还原、超时重试、`cache/media/` 命中即跳过、`sha256` 记录。
- 并发限制在 **2** 以内，请求间加 300–800ms 抖动延时，避免触发风控。
- **验收**：对 1 个真实录播跑通，产出音频文件且能被播放器正常播放、时长与网页显示一致（误差 < 2%）。

**M3 — 转写**

- 抽象接口 `Transcriber.transcribe(audio_path) -> Transcript(segments)`，默认实现 **OpenAI 兼容的 `/v1/audio/transcriptions`**（`base_url` / `api_key` / `model` / 语言 / 是否要时间戳 全部走配置）。
- **重要事实**：DeepSeek 开放平台目前只有 `deepseek-chat` / `deepseek-reasoner` 这类**文本**模型，**没有 ASR（语音转文字）接口**。所以：
  - ASR 走上面那个可配置的 OpenAI 兼容端点（可接硅基流动、阿里百炼、讯飞、或本地 `faster-whisper` / `whisper.cpp` 的 OpenAI 兼容服务）；
  - **DeepSeek 用于转写后的文本加工**：错别字与标点修复、课程专业术语纠正、口语冗余清理、按语义重新分段、生成结构化摘要与大纲。这一段是可选开关。
  - 在 `README.md` 和 GUI 设置页里把这两件事写清楚，别让用户以为「填了 DeepSeek key 就能直接转写」。
- 实现要点：单文件超过端点体积上限（常见 25MB）时按**静音切分**，单段 ≤ 10 分钟，段间重叠 1–2 秒，拼接时按时间轴去重；指数退避重试（最多 4 次）；失败段落单独记录，可续跑。
- 产出：`<标题>.srt`（带时间轴）、`<标题>.txt`（纯文本）、`<标题>.md`（标题 + 元信息 + 摘要 + 全文）。
- **验收**：对 1 个真实录播产出三份文件；我人工抽 3 段比对，意思无错漏，时间戳与音频位置基本对得上。

**M4 — GUI**

- 单窗口三栏：
  - 左：课程 → 录播树，带搜索框、全选/反选、显示时长合计、显示是否已转写；
  - 中：任务队列（每行：标题 / 阶段 / 进度条 / 重试次数 / 错误详情 / 「打开输出目录」）；
  - 右：实时日志（可复制、可清空）。
- 顶部操作：`登录 / 刷新清单 / 加入队列 / 开始 / 暂停 / 停止 / 设置 / 打开输出目录`。
- 勾选多条 → 批量入队；后台用独立工作线程或进程池执行「下载 + 转写」，**UI 全程不卡死**（用信号/槽回传进度，不要在工作线程里碰 UI 对象）。
- 设置页：ASR base_url / api_key / model、DeepSeek api_key（用于后处理）、输出目录、并发数、是否保留音频、是否生成 srt。
- 凭据用 Windows DPAPI（`win32crypt` / `keyring`）加密保存，**明文密码绝不写进源码、配置文件或日志**。
- 关窗时保存队列，重开后任务状态从 `state.db` 恢复。
- **验收**：冷启动 → 登录 → 刷新 → 勾 2 条 → 开始 → 全部变成「完成」，且输出目录里有 6 个文件（每条 3 个）。贴截图路径与日志到 `PROGRESS.md`。

**M5 — 打包交付**

- PyInstaller 打包，内嵌 `ffmpeg.exe`；产物 `dist/大夏学堂转写助手/大夏学堂转写助手.exe`，双击可运行，在没有 Python 的干净环境也能启动（至少在同机新建用户下验证）。
- `README.md` 必须包含：环境要求、安装步骤、首次运行引导、API 申请说明、常见错误（登录失效 / 接口变更 / ffmpeg 缺失 / ASR 限流）与解决办法、免责与合规声明。
- **验收**：在 `dist/` 里双击 exe 走完一次完整流程。

**M6 — 加固与交付说明**

- 单元测试：清单解析、分片切分、时间轴拼接去重、任务状态机（`pytest`，不依赖网络的部分用录制的 fixture）。
- `CHANGELOG.md` 记录接口与版本变化点。
- 最后输出一份**面试级**总结：架构图（文字版即可）、模块职责、数据流、已知限制、后续可做的事。

### 4. 完成定义（DoD）

全部满足才算完成，缺一不可：

1. `dist/` 下有可双击运行的 exe，且在同机重新打开能跑通 M4 的验收流程。
2. 用我的真实账号能列出我账号内**全部**可访问录播，条数与网页端一致。
3. 至少 2 条视频端到端产出 `.txt` / `.srt` / `.md`，人工抽检内容正确。
4. 中断后重新打开应用，未完成任务能从断点继续（下载不重下、转写不重跑）。
5. 工作区无明文密码、无明文 Cookie、无 token 提交；`recon/` 与 `storage_state.json` 已加入 `.gitignore`。
6. `README.md` / `docs/API.md` / `PROGRESS.md` 齐全且内容与代码一致。

### 5. 风险与降级预案（遇到就照这个走，并在 `PROGRESS.md` 里记录）

| 风险 | 应对 |
| --- | --- |
| 统一身份认证有图形验证码 / 短信二次验证 | **不绕过**。改为「一次性人工登录 + 持久化浏览器 profile + 复用 storage_state」的方案，并在 GUI 首启引导里明确写「需要手动登录一次」。 |
| 登录态频繁失效 | 增加 `AuthExpiredError` 后的一键「重新登录」按钮；把刷新清单做成幂等操作。 |
| 视频接口带动态签名 / 加密参数 | 用 Playwright 在**已登录页面上下文内**发起请求（借浏览器环境算签名），再把结果喂给 httpx 下载。 |
| 视频是 DRM（Widevine / PlayReady） | 明确判定并**停止**，在 `PROGRESS.md` 写清证据，向我说明不可行，不要尝试破解。 |
| 平台限流 / 风控 | 降并发（2 → 1）、拉长延时、加随机 User-Agent 与 Referer，失败退避重试；把速度上限做成设置项。 |
| ASR 端点体积/时长限制 | 静音切分 + 段落重叠 + 时间轴偏移合并（M3 已要求）。 |
| 转写成本或精度不达预期 | 让端点和模型可切换，提供「先用 1 分钟短样本试转」的按钮来验证单价与质量。 |
| PySide6 打包体积大 / 打包失败 | 退 `--onedir`；再不行退 Tkinter 并记录原因。 |

### 6. 禁止事项

- 不把账号、密码、Cookie、token 写进任何会被提交的文件或日志输出。
- 不破解、不绕过 DRM 与身份验证，不做验证码识别。
- 不把抓取到的音频/文本上传到除用户自己配置的 ASR / LLM 端点之外的任何第三方。
- 不删除用户原始数据；所有下载与转写产物只增不改。
- 不为了「看起来完成」而伪造输出文件或跳过真实验收。

### 7. 我（用户）能提供的

- 学号与密码：**首次登录时由我在弹出的浏览器里手动输入**（不要让我把密码贴进代码或配置文件）。
- ASR 端点的 API Key：M3 之前我会给你；若我还没给，就先把 `Transcriber` 接口和本地 `faster-whisper` 兜底实现做好。
- 中途配合完成验证码 / 二次验证。

## 三、备注

- 目标模式建议同时设置：`max_goal_rounds = 40`，并在每轮结束后让它先读 `PROGRESS.md` 再继续，避免重复劳动。
